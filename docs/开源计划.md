## 还要不要重写历史、重建仓库

都不需要。理由：

- 没扫到真密钥、真 Team ID、私人邮箱或电话。
- 仓库已经公开三天，重写也收不回别人可能已经拉走的副本。以后真发现泄露，**先换掉那个密钥**（Cloudflare secret、Google OAuth 密钥、APNs 密钥），重写历史只是补充。

要是以后还是想重写或重建，会坏的东西：

- 所有提交号都变：各个 worktree（collab-ui、multi-org、remote-desktop-web 等）的分支基于旧 main，要逐个 rebase 到新 main，否则推上去会把旧历史带回来；记忆和文档里写的提交号全部失效。
- 发版流程（云端 `wrangler deploy`、电脑 App 上传 R2、TestFlight）不依赖提交号，不会坏；但正在跑的会话推 main 时会被拒。
- 重建仓库会丢 star、issue 和 GitHub 设置。

## 以后推 main 前

- 本仓库 `git config --local user.email` 是隐私邮箱；全局还是工作邮箱。新 clone 或新机器要先设本地邮箱，推之前看一眼 `git log -1 --format='%ae %ce'`。
- 加了真名、联系方式、密钥文件或截图时，按上面的办法再扫一遍。
- 本机主检出的本地 main 落后 origin/main，又放着和 origin/main 同名的未跟踪文件，`git pull` 会拒绝。那些文件内容和 origin/main 一样，删掉再拉就行。
