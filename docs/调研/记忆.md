# Pupu 的长期记忆：调研

> 日期：2026-11-08
> 要回答的是需求说明 4.7「记忆：个人和共享分开」留下的问题：数据怎么存、每一轮装哪些、谁能看谁能改、什么时候写、在对话里怎么留痕、三端界面放哪；还有有了私聊以后，个人记忆谁能看。
> 看了四个开源项目和 Grok Bot 0.78。代码都在本机 `references/` 下，只读没跑，下文路径相对 `references/`。
> 2026-11-04 的草稿「组织大脑-pi-durable做法.md」里 pi-durable 那部分，本文重新核对过，结论写在第 4 节。

## 0. 结论

- **四家都没有现成的「一个团体、各人私聊、三层记忆」。** mem0 按 id 分范围但不查归属；hermes-agent 一个档案一份记忆；OpenClaw 默认只有一个主人。Grok Bot 0.78 的 Team Bot 最像 Pupu：个人记忆和团队记忆分开，个人的要本人挑出来才进团队。可见范围要 Pupu 自己定，靠服务端的规则拦，不能只写在提示词里。
- **记什么由模型调工具写，每次都在对话里留一行。** 后台静默提取（mem0）会越记越多，要另一套模型去清理；hermes-agent 和 OpenClaw 的主路径都是模型显式写，Hermes 在聊天里提示「Memory updated」。Pupu 先只做显式写，不做静默提取。
- **记忆要小，满了让模型合并。** hermes-agent 给每份记忆一个字数上限，满了写入就失败，让模型把几条并成一条再写。这比检索简单，也让记忆一直能全量放进提示词。Pupu 一个团体的人少，先全量放，不做检索。
- **记忆放在最新一条用户消息前面，不放系统提示。** pi 把系统提示的每次变化都写进会话记录，而且整段系统提示在请求最前面，一变缓存就全失效。每一轮装的是发起人的个人记忆，大家轮流说话时它来回变，放系统提示代价最大。hermes-agent 每轮的召回内容也是挂在用户消息上。
- **旧条目标结束，不真删。** Graphiti 给事实标 `invalid_at`，mem0 记 history 表。Pupu 合起来做：改就是旧条结束、新条接上，谁改的、从哪条会话来的都在行上。只有个人记忆被本人删、成员被移除时真删。
- **记忆是资料，不是指令。** 四家里只有 OpenClaw 在结构上防：不是主人说的内容标成不可信，不自动进记忆。Pupu 的会话是多人的，模型只能记发起人自己说的、或者大家定下的事；从邮件、网页、文件读到的话，用户没让记就不记。写入前拦掉像密钥的内容。

## 2. 按问题对比

### 2.1 分层和范围

- **mem0**：只有 `user_id`、`agent_id`、`run_id` 三个 id，写入时至少带一个（`mem0/mem0/memory/main.py:314-404`）。读时没给的 id 等于「都匹配」，所以按 `agent_id` 查会查出所有人的（`main.py:1458-1475`）。按记忆 id 读、改、删、看历史都不查归属（`main.py:1222-1233`、`1829-1879`）。一次查询不能跨几个范围，要分开查再合并。
- **hermes-agent**：一个档案两份文件，`MEMORY.md` 放环境和约定，`USER.md` 放用户画像（`hermes-agent/tools/memory_tool_store.py:188`）。没有按人、按群分；谁能跟 bot 说话，谁就能改同一份 `USER.md`。「caller scope」说的是一个进程服务几个档案时别串，不是区分人（`agent/memory_caller_scope.py:1-16`）。
- **OpenClaw**：`USER.md` 和 `MEMORY.md` 每次开会话都装，每天的笔记按需检索（`openclaw/docs/concepts/memory.md:28-62`）。模板里写着长期记忆只在和主人的私聊里装，群聊里不装（`docs/reference/templates/AGENTS.md:67`），但这只是提示词约定。群里不是主人的人说的话标成 `untrusted`，不自动装、不升级成长期记忆（`docs/concepts/memory-architecture.md:80-84`、`189-192`）。跨会话召回在代码里做了「拿不准就不给」（`extensions/memory-core/src/session-search-visibility.ts:49-106`）。
- **Grok Bot 0.78**：个人记忆和团队记忆两层，个人的要本人点名提升才进团队（`promoteGrokBotMemoriesToTeam({factIds})`）。各人和 bot 的私聊连创建者、管理员都看不到。

对 Pupu：三层（个人、项目、共享）比各家都多一层，但都在一个 DO 的 SQLite 里，按「层 + 归属」两列分就够。可见范围由服务端判，提示词只是第二道。

### 2.2 什么时候写

- **mem0**：每次 `add()` 跑一遍模型，从这一轮对话里抽事实，提示词是「拿不准就抽」（`mem0/configs/prompts.py:578`）。现在这版只会加，不会改和删（`docs/migration/oss-v2-to-v3.mdx:16`），新旧事实都留着，清理靠收费的 Dream 功能（`docs/platform/features/dream.mdx:10-15`）。
- **hermes-agent**：模型调 `memory` 工具写，工具说明里写「只记每次会话都用得上的事」（`tools/memory_tool.py:384-385`），任务进展这类不记（`:394-396`）。另有后台复盘，但没人看着时只准加，改和删要先等人批（`memory_tool.py:179-219`）。
- **OpenClaw**：用户说「记住」时模型直接写文件（`AGENTS.md:73-77`）。压缩前跑一轮静默的「memory flush」，只准往当天笔记里追加（`extensions/memory-core/src/flush-plan.ts:13-32`）。

对 Pupu：先只做模型显式写。人说「记住」就记；模型自己判断以后每次都用得上的（偏好、分工、定下的规矩）也可以记，但每次都留一行，人看到不对可以马上说。压缩前扫一遍项目留到第二批。

### 2.3 去重、改和删

- **hermes-agent**：没有 id，按唯一子串找条目，找到多条就报错（`tools/memory_tool_store.py:74-126`、`479-482`）。一模一样的直接跳过。满了写入失败，模型要在一批操作里删旧、并旧、加新，最后的结果不超限才算（`store:329-337`、`618-629`）。
- **mem0**：给模型看旧条目时把 UUID 换成小整数，免得模型编 id（`main.py:935-940`）。去重只比 MD5，近似的和矛盾的会越积越多（`oss-v2-to-v3.mdx:360`）。
- **Graphiti**：新事实和旧事实矛盾时，旧事实的 `invalid_at` 设成新事实的 `valid_at`，从不删除（`graphiti/graphiti_core/utils/maintenance/edge_operations.py:715-783`）。判矛盾要有「旧事实已经结束」的明确证据，单靠时间新不算（`prompts/dedupe_edges.py:86-88`）。

对 Pupu：用 SQLite 的整数 id，给模型看成 `#12`。改一条就是旧条标结束、新条记 `replaces`。写满报错，列出现有条目，让模型先合并。

### 2.4 怎么装进提示词

- **hermes-agent**：自己的两份记忆在会话开始时拍一张快照放进系统提示，会话中途写的不改提示词，为的是前缀缓存（`tools/memory_tool.py:2-4`、`store:177-180`）。代价是长会话里新记的看不到，要 `/new`（`website/docs/user-guide/features/memory.md:61-65`）。外接记忆每轮召回，包在 `<memory-context>` 里挂在用户消息上（`agent/memory_context.py:169-185`）。
- **OpenClaw**：`MEMORY.md` 和 `USER.md` 开会话时装，超长截断（`docs/concepts/memory.md:74-79`）。

对 Pupu：Pupu 的聊天是一条永远不结束的会话，「开会话时拍快照」不成立。见第 4 节。

### 2.5 检索

- **mem0**：候选只从向量检索来，BM25 只是加分（`oss-v2-to-v3.mdx:381`），关键词用的是英文 spaCy，中文不分词。没有向量就搜不了。
- **OpenClaw**：SQLite FTS5（BM25）加向量。中文要换 trigram 分词器，三个字以下的词退回子串匹配（`docs/reference/memory-config.md:832-838`、`extensions/memory-core/src/memory/manager-search.ts:303-312`）。没有向量时只走关键词。判断「这句话是在问以前的事」的正则有中文（还记得、之前、上次…聊过）（`extensions/active-memory/escalation.ts:22-29`）。

对 Pupu：一个团体的记忆量小，又有字数上限，先全量装，不做检索。以后要查已结束的旧条目，用 `LIKE` 子串匹配；FTS5 trigram 在 DO 里能不能用，到时候再实测。

### 2.6 留痕和审计

- **mem0**：history 表记 `old_memory`、`new_memory`、`event`、`actor_id`、时间（`mem0/memory/storage.py:102-121`）。没有范围列，也连不回来源消息。删是真删，只剩 history 行。
- **Graphiti**：每个事实记着产生它的 episode，episode 也记着它产生了哪些事实（`graphiti_core/edges.py:263-288`、`nodes.py:318-327`）。
- **OpenClaw**：每段记忆记来源类别（主人、Agent、不可信、系统）、会话、时间，来源从不默认成「主人」（`docs/concepts/memory-architecture.md:77-93`）。
- **hermes-agent**：聊天里默认提示「Memory updated」，详细模式显示改了什么（`website/docs/user-guide/features/memory.md:364-392`）。

对 Pupu：每条记忆的行上就记着谁加的、在哪条会话、什么时候；改和删记结束时间和谁结束的。对话里的那一行就是给人看的审计。

### 2.7 安全

- **hermes-agent**：写入前扫注入和外传的模式，装载时命中的条目换成占位，原文留着给人删（`tools/memory_tool_store.py:223-238`）。召回内容标着「不是新的用户输入」，但又说是「权威资料」，这句不可取（`agent/memory_context.py:180-182`）。
- **OpenClaw**：外部内容包在 `<<<EXTERNAL_UNTRUSTED_CONTENT>>>` 里（`extensions/active-memory/query.ts:116`）；模板写着「密钥不记，除非用户要」（`AGENTS.md:57`）。
- **mem0**：没有防记忆里藏指令的措施。

对 Pupu：多人共用，一个人记下的话会装进别人的轮。所以（1）记忆块明说是资料，和这次说的冲突时以这次为准；（2）只记发起人自己说的、或者在会话里定下的事；（3）写入前拦掉像密钥、口令、验证码的内容；（4）记忆里的【发送者：】抬头一样改掉，不让冒充。

## 3. 用户怎么看、怎么改

- hermes-agent：命令行 `hermes journey list/delete/edit` 浏览和删改（`website/docs/user-guide/features/memory.md:263-281`）；打开写入审批后，写入先排队，人批了才落（`:329-362`）。
- OpenClaw：`forget --participant` 按人删（`docs/concepts/memory-provenance.md:191-195`）。
- Grok Bot：设置里列出个人记忆，挑几条提升到团队。

对 Pupu：设置里放一页「记忆」，三端一样，按层分组，能删能改；聊天里的那一行点一下就到这页。

## 4. Pupu 这边的约束

都在 `apps/cloud/node_modules/@earendil-works/` 下核对过。

- **系统提示每变一次就写一条记录。** `registry.install` 的 section 每次请求前都渲染，变了 pi 就往会话里追加一条 `pi.system`，带整段新文字（`pi-durable/dist/harness/prompt.js` 的 `planSections`）。发请求时所有 `pi.system` 合成最前面的一条系统消息（`pi-ai/dist/utils/transcript.js` 的 `getCurrentSystemMessage`）。所以系统提示一变，DeepSeek 的前缀缓存从头失效。现在 `prompt.ts` 的「当前的项目」已经在系统提示里，项目每报一次进展都会这样，这是已有的问题，不在本次范围。
- **`beforeRequest` 改的消息只用这一次。** `GenerationHooks.beforeRequest` 的返回值「只用于这次请求」（`pi-durable/dist/harness/types.d.ts:690`），不进记录，压缩也吞不掉。记忆放在这里，挂在这一轮在答的那条用户消息上：一轮里的多次工具往返前缀不变，缓存照样命中；换一轮只丢上一轮那一段的缓存。
- **只带 `kind` 和 `data` 的写入，模型看不到，跑到一半也能追加**（`types.d.ts:597`）。在设置里删共享记忆时，用它在「大家」里留一行，不打断正在跑的一轮。
- **pi 自带的 BM25 不认中文。** `tokenize` 按 `[^a-z0-9]+` 切（`pi-durable/dist/search.js:44`），中文全丢。草稿里这条是对的。
- **一轮替谁做。** 发送者现在记在 `pupu.sent` 记录上，模型看第一行【发送者：】（`src/messages.ts`）。还没有「这一轮替谁做」的字段，4.8 也等着它。记忆要靠它选个人记忆，所以要先补上：聊天里是这一轮在答的那条消息的发送者；项目里转交来的，是在聊天里让 Pupu 转交的那个人。
- **私聊。** `threads.ts` 已经能分大家、私聊、项目。

## 5. 借什么，不借什么

**借：**
- Grok Bot：个人和团队分开，个人的不会自己混进团队；挂在某人名下的东西只认这个人发起的轮。
- hermes-agent：每层一个字数上限，满了报错让模型合并；写入前扫内容；聊天里提示记了什么。
- Graphiti：旧条目标结束不删除，新条记着它替了哪条。
- mem0：给模型看小整数 id；history 的列（谁、改前、改后、什么时候）。
- OpenClaw：私聊里的个人内容不进群聊；记忆的来源记清楚，从不默认成「本人说的」。

**不借：**
- mem0 的每轮自动提取和向量检索：要另一个模型调用和向量库，中文也不分词。
- hermes-agent 的会话开始拍快照：Pupu 的聊天不结束，快照会一直旧。
- OpenClaw 的检索子 Agent（最多等 15 秒）和每天笔记：记忆量小用不上。
- 外接 mem0、Graphiti 服务：要 Python 和向量库或图数据库，和 Workers 对不上。
